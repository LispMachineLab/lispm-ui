#+title: LispM UI

#+HTML: <p align="center"><a href="https://github.com/LispMachineLab/lispm-ui/actions/workflows/test.yml"><img src="https://github.com/LispMachineLab/lispm-ui/actions/workflows/test.yml/badge.svg" alt="test" /></a></p>

The classic-style interface that LispM and its applications are drawn with, in any Emacs 30.1 or
later, graphical or on a text terminal: its controls, forms, alerts, menus and dialogs, and the
keys that work every one of them from the keyboard alone.  An application requires it and looks
the same wherever it is shown, on LispM's desktop or in plain Emacs.  In code, the prefix is
~lispm-ui-~.

* What it holds

| =lispm-ui-base.el=    | where it is; whether a frame is a text terminal, where controls are drawn in text; lengths in pixels, counted in cells there |
| =lispm-ui-i18n.el=    | the language its words are shown in, and their translations, =i18n/=                                                     |
| =lispm-ui-palette.el= | the colours it draws in, derived from the colour theme, and its faces                                                    |
| =lispm-ui-look.el=    | the looks it draws in, each the forms of one system's interface, and families of looks drawn alike                      |
| =lispm-ui-text.el=    | text laid out in pixels: widths, fitting with an ellipsis, aligning, breaking lines, Chinese and Japanese type          |
| =lispm-ui-draw.el=    | what it draws with: SVG primitives, text and pictures drawn as Emacs shows them, and the cache of drawn images          |
| =lispm-ui-raster.el=  | pictures drawn in text, in block characters, and as PNGs, for text terminals                                            |
| =lispm-ui-icons.el=   | icons found by name: an interface's own, through a hook, and those its alerts show                                      |
| =lispm-ui-controls.el= | its controls: push buttons and the default one's ring, pop-up menus, bevel buttons, radio buttons, check boxes, group boxes |
| =lispm-ui-list.el=    | lists' column headings, the column sorted by pushed in, and disclosure triangles                                      |
| =lispm-ui-scroll.el=  | scroll bars: where the thumb stands for what shows, and the bar drawn                                                  |
| =lispm-ui-window.el=  | windows' title bars, laid out and drawn, as a dialog's title                                                           |
| =lispm-ui-modal.el=   | what its modal panels share: reading events without quitting, what each key does, focus rings, holding a control pressed |
| =lispm-ui-ask.el=     | asking a person: an alert, a question to agree to, a choice, a file                                                      |
| =lispm-ui-popup.el=   | panels popped up over a frame, in child frames, holding their size                                                      |
| =lispm-ui-alert.el=   | alerts, drawn as Mac OS 9 drew them, or in text on a text terminal                                                      |
| =lispm-ui-menu.el=    | menus, drawn as Mac OS 9 drew them, submenus beside their items; choices shown in one                                   |
| =lispm-ui-form.el=    | forms, written as data                                                                                                   |

=lispm-ui.el= loads every part.  More come as LispM's interface moves here: next, a dialog choosing
a file.

* Controls

Each control is drawn as SVG by a generic function, as ~lispm-ui-draw-push-button~, in the colours
of the palette; as a string displaying it, as ~lispm-ui-push-button~, to put on a line, which a text
terminal shows as text; and as a button inserted in a buffer, as ~lispm-ui-insert-push-button~:

#+begin_src emacs-lisp
(lispm-ui-insert-push-button "Save" #'save-buffer :default t)
(lispm-ui-insert-check-box "Wrap lines" visual-line-mode #'visual-line-mode)
(lispm-ui-insert-popup-button "Red" '((red . "Red") (blue . "Blue")) #'my-set-colour :current 'red)
#+end_src

=TAB= and =S-TAB= go from one to the next, as buttons do; the one point is on is drawn ringed when
~lispm-ui-show-focus~ runs from ~post-command-hook~, and =RET= or =SPC= presses it, drawn pushed in
as it is.

* Colours and looks

What LispM UI draws takes its colours from a palette derived from the colour theme in use, so any
theme draws it.  ~lispm-ui-palette-follow-theme~ derives it now and again as a theme is enabled;
whatever shows LispM UI may name colours outright with a function of ~lispm-ui-palette-functions~,
and colour its own faces on ~lispm-ui-palette-changed-hook~.  Each drawing is a generic function
whose default method draws the classic look; a look, named by ~lispm-ui-look~, draws its own forms
in methods specialized on it, or on its family of looks (see =lispm-ui-look.el=).

* Icons

~lispm-ui-icon~ shows an icon by its name, as an image, or on a text terminal as a character in
the icon's colour; ~lispm-ui-icon-picture~ draws it there in block characters instead.  LispM UI
has the icons its alerts show, =caution=, =stop= and =note=; an interface with icons of its own
finds them with a function of ~lispm-ui-icon-functions~:

#+begin_src emacs-lisp
(add-hook 'lispm-ui-icon-functions
          (lambda (name)
            (let ((file (expand-file-name (format "%s.svg" name) my-icons)))
              (and (file-readable-p file) file))))
#+end_src

* Forms

A form is written as data, a title and its fields, and drawn as a dialog with Emacs's widgets:

#+begin_src emacs-lisp
(lispm-ui-form "New Character"
  '((title :type text :label "Name" :required t)
    (avatar :type picture :label "Picture")
    (soul :type text-area :label "Soul" :lines 8))
  :submit "Create"
  :on-submit (lambda (values) (message "%S" values)))
#+end_src

Fields are of the types ~lispm-ui-form-types~ lists: text, passwords, text areas, pictures, pop-up
menus, radio buttons, check boxes, rows of buttons, lists of things a row each with buttons of
their own, statuses, and headings that start a group.  =TAB= goes from field to field, =C-c C-c=
submits, =C-c C-k= cancels.

A field's =:on-change= is called each time it is changed, and may change the others with
~lispm-ui-form-set~, which says a status again where it stands, as how a connection went, the rest
of the form left as it is.  A form made =:instant= applies each change as it is made, as an
application's settings do, with no Cancel button:

#+begin_src emacs-lisp
(lispm-ui-form "Mail Settings"
  `((reading :type heading :label "Reading")
    (html :type check :text "Show HTML when a message has it" :value ,my-prefer-html
          :on-change ,(lambda (on) (customize-save-variable 'my-prefer-html on))))
  :instant t
  :submit "Done"
  :mode #'my-settings-mode)
#+end_src

=:mode= puts the form in a mode of its own, derived from ~lispm-ui-form-mode~, for its keys and
menus, and =:setup= sets its buffer up before it is drawn.  Once LispM UI has a palette, a form is dressed
in its look: its buttons, check boxes, radio buttons and pop-up menus are LispM UI's controls, its
groups framed in group boxes, its fields in the content's colour on the chrome's ground, and what the
keyboard is on ringed in the focus colour; without one it is drawn as text.  An application drawing a form with
Emacs's widgets itself has it dressed the same with ~lispm-ui-form-dress~, and whatever shows a
form may dress it otherwise: see the Commentary of =lispm-ui-form.el=.  A program written for
LispM's forms before they moved here, which requires ~lispm-form~, finds them by their former names.

* Asking a person

~lispm-ui-alert~, ~lispm-ui-confirm~, ~lispm-ui-choose~ and ~lispm-ui-choose-file~ ask in the
minibuffer, never in the system's own dialogs, unless something draws them.  LispM UI draws an
alert, and a pop-up menu's choices, itself, as Mac OS 9 drew them, once it has a palette: over the
selected frame, or in text on a text terminal whose Emacs shows child frames, as Emacs 31's does.  An interface drawing them its
own way sets ~lispm-ui-alert-function~, ~lispm-ui-choose-function~ or
~lispm-ui-choose-file-function~.

* Menus

~lispm-ui-menu~ pops up a menu of items, plists of =:label=, =:action=, =:enabled=, =:checked=,
=:key=, =:icon= and =:submenu=, or the symbol =separator=, and runs the action of the one chosen;
~lispm-ui-menu-choose~ only returns it.  The arrows, or =C-n=, =C-p=, =C-f= and =C-b=, move
through it and its submenus, a letter goes to the item it starts, =RET= chooses and =ESC= gives up;
where no menu can pop up, it is chosen from in the minibuffer.

#+begin_src emacs-lisp
(lispm-ui-menu `((:label "Open…" :action find-file)
                 separator
                 (:label "Wrap Lines" :action visual-line-mode :checked ,visual-line-mode)))
#+end_src

* The keyboard

Every panel works from a keyboard without arrow or function keys, as the HHKB is: =C-f=, =C-b=,
=C-n= and =C-p= go where the arrows do, =TAB= and =S-TAB= ring the next and previous control,
=RET= chooses, =SPC= presses the control ringed, and =ESC= or =C-g= gives up.

* Its words, in the language spoken

Its words are written in English and shown in English, German, French, Japanese or Chinese,
Simplified or Traditional: the language ~lispm-ui-language~ names, else that of the program
showing it, else the computer's.  [[https://github.com/LispMachineLab/lispm-kit][LispM Kit]] translates them, as it does every LispM
program's words; LispM UI keeps only its catalogs, =i18n/=.  A program says its language with a function of
~lispm-ui-language-functions~, and calls ~lispm-ui-language-changed~ when it speaks another:

#+begin_src emacs-lisp
(add-hook 'lispm-ui-language-functions (lambda () my-language))
#+end_src

* Installing it

LispM installs it, and its App Store installs it before the applications that need it.
Elsewhere, from git, after LispM Kit, which it requires:

#+begin_src emacs-lisp
(package-vc-install "https://github.com/LispMachineLab/lispm-kit")
(package-vc-install "https://github.com/LispMachineLab/lispm-ui")
#+end_src

An application names it in its =Package-Requires=, as ~(lispm-ui "0.4.0")~, and requires the part
it uses, or ~lispm-ui~ for all of them.

* Testing

=make test compile= runs the tests and byte-compiles the sources, warnings counted as errors,
with a checkout of LispM Kit beside this one, or where =LISPM_KIT= says.
=make i18n= lists the messages each catalog lacks, and those it holds that the code no longer
gives.  The palettes, drawings and lines LispM UI makes are those LispM's desktop made before
they moved here, which =test/golden.eld= keeps: =make golden LISPM_DESKTOP=… LISPM_AGENT=…= writes
it again from a checkout of the desktop from then and LispM's agent (see =test/lispm-ui-golden.el=).  =make gallery= draws every
control in each of its states, light and dark, in =gallery/=, with =gallery/index.html= to look at
them in a browser.
