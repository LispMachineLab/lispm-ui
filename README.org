#+title: LispM UI

#+HTML: <p align="center"><a href="https://github.com/LispMachineLab/lispm-ui/actions/workflows/test.yml"><img src="https://github.com/LispMachineLab/lispm-ui/actions/workflows/test.yml/badge.svg" alt="test" /></a></p>

The classic-style interface that LispM and its applications are drawn with, in any Emacs 30.1 or
later, graphical or on a text terminal: its controls, forms, alerts, menus and dialogs, and the
keys that work every one of them from the keyboard alone.  An application requires it and looks
the same wherever it is shown, on LispM's desktop or in plain Emacs.  In code, the prefix is
~lispm-ui-~.

* What it holds

| =lispm-ui-base.el=    | where it is; whether a frame is a text terminal, where controls are drawn in text; lengths in pixels, counted in cells there |
| =lispm-ui-i18n.el=    | the language its words are shown in, and their translations, =i18n/=                                                     |
| =lispm-ui-palette.el= | the colours it draws in, derived from the colour theme, and its faces                                                    |
| =lispm-ui-look.el=    | the looks it draws in, each the forms of one system's interface, and families of looks drawn alike                      |
| =lispm-ui-text.el=    | text laid out in pixels: widths, fitting with an ellipsis, aligning, breaking lines, Chinese and Japanese type          |
| =lispm-ui-draw.el=    | what it draws with: SVG primitives, text and pictures drawn as Emacs shows them, and the cache of drawn images          |
| =lispm-ui-modal.el=   | what its modal panels share: reading events without quitting, what each key does, focus rings, holding a control pressed |
| =lispm-ui-ask.el=     | asking a person: an alert, a question to agree to, a choice, a file                                                      |
| =lispm-ui-form.el=    | forms, written as data                                                                                                   |

=lispm-ui.el= loads every part.  More come as LispM's interface moves here: drawn controls, alerts,
menus, and a dialog choosing a file.

* Colours and looks

What LispM UI draws takes its colours from a palette derived from the colour theme in use, so any
theme draws it.  ~lispm-ui-palette-follow-theme~ derives it now and again as a theme is enabled;
whatever shows LispM UI may name colours outright with a function of ~lispm-ui-palette-functions~,
and colour its own faces on ~lispm-ui-palette-changed-hook~.  Each drawing is a generic function
whose default method draws the classic look; a look, named by ~lispm-ui-look~, draws its own forms
in methods specialized on it, or on its family of looks (see =lispm-ui-look.el=).

* Forms

A form is written as data, a title and its fields, and drawn as a dialog with Emacs's widgets:

#+begin_src emacs-lisp
(lispm-ui-form "New Character"
  '((title :type text :label "Name" :required t)
    (avatar :type picture :label "Picture")
    (soul :type text-area :label "Soul" :lines 8))
  :submit "Create"
  :on-submit (lambda (values) (message "%S" values)))
#+end_src

Fields are of the types ~lispm-ui-form-types~ lists: text, text areas, pictures, pop-up menus,
radio buttons, check boxes, rows of buttons and headings that start a group.  =TAB= goes from field
to field, =C-c C-c= submits, =C-c C-k= cancels.  Whatever shows a form may dress it: see the
Commentary of =lispm-ui-form.el=.  A program written for LispM's forms before they moved here,
which requires ~lispm-form~, finds them by their former names.

* Asking a person

~lispm-ui-alert~, ~lispm-ui-confirm~, ~lispm-ui-choose~ and ~lispm-ui-choose-file~ ask in the
minibuffer, never in the system's own dialogs, unless an interface draws them: it sets
~lispm-ui-alert-function~, ~lispm-ui-choose-function~ or ~lispm-ui-choose-file-function~.

* The keyboard

Every panel works from a keyboard without arrow or function keys, as the HHKB is: =C-f=, =C-b=,
=C-n= and =C-p= go where the arrows do, =TAB= and =S-TAB= ring the next and previous control,
=RET= chooses, =SPC= presses the control ringed, and =ESC= or =C-g= gives up.

* Its words, in the language spoken

Its words are written in English and shown in English, German, French, Japanese or Chinese,
Simplified or Traditional: the language ~lispm-ui-language~ names, else that of the program
showing it, else the computer's.  [[https://github.com/LispMachineLab/lispm-kit][LispM Kit]] translates them, as it does every LispM
program's words; LispM UI keeps only its catalogs, =i18n/=.  A program says its language with a function of
~lispm-ui-language-functions~, and calls ~lispm-ui-language-changed~ when it speaks another:

#+begin_src emacs-lisp
(add-hook 'lispm-ui-language-functions (lambda () my-language))
#+end_src

* Installing it

LispM installs it, and its App Store installs it before the applications that need it.
Elsewhere, from git, after LispM Kit, which it requires:

#+begin_src emacs-lisp
(package-vc-install "https://github.com/LispMachineLab/lispm-kit")
(package-vc-install "https://github.com/LispMachineLab/lispm-ui")
#+end_src

An application names it in its =Package-Requires=, as ~(lispm-ui "0.1.0")~, and requires the part
it uses, or ~lispm-ui~ for all of them.

* Testing

=make test compile= runs the tests and byte-compiles the sources, warnings counted as errors,
with a checkout of LispM Kit beside this one, or where =LISPM_KIT= says.
=make i18n= lists the messages each catalog lacks, and those it holds that the code no longer
gives.  The palettes, drawings and lines LispM UI makes are those LispM's desktop made before
they moved here, which =test/golden.eld= keeps: =make golden LISPM_DESKTOP=…= writes it again from a
checkout of the desktop from then (see =test/lispm-ui-golden.el=).
